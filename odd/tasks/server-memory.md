# Configurable server memory (Project Zomboid heap)

Goal: the JVM heap becomes a setting of the manager, editable from `create`, `config` and the TUI,
instead of a value buried in the game's launcher json. Project Zomboid only: Core Keeper and Don't
Starve Together run without a heap flag, so the field belongs to them in no way.

Branch: `feat/server-memory` (from `origin/main`). Delivery: `ask-on-risk`. Tests: `go test ./...`,
`go test -race ./...`, `go vet ./...`, `gofmt -l .`.

## Specs

- S1. `gamehost create` and `gamehost config` accept `--memory` (`[--memory 4g]`). The flag is owned
  by `projectzomboid` only: `create <other game> --memory 4g` and `config <other game> --memory 4g`
  fail with a usage error naming the owner, exactly like `--admin-password` today.
- S2. Accepted values are a positive integer plus a JVM unit (`k`, `m`, `g`), case-insensitive,
  normalized to lowercase (`"4G"` becomes `"4g"`). At least `512m`, because the server cannot boot
  below that. Anything else is `instance.ErrInvalid` with the value in the message: `"4"`, `"g"`,
  `"0g"`, `"4x"`, `"-4g"`, `"4 g"`, `"256m"`.
- S3. An empty value means `instance.DefaultProjectZomboidMemory` (`"8g"`), the heap the dedicated
  server ships with. `config <name> --memory ""` restores that default. `instance.json` stores an
  empty field in both cases, so an instance created before this feature keeps working untouched.
- S4. Before every launch, the driver rewrites exactly the `-Xmx` entry of `vmArgs` in
  `<InstallDir>/ProjectZomboid64.json` with the effective value. Every other top-level key and every
  other `vmArgs` entry survives; when `vmArgs` has no `-Xmx`, the entry is appended. The file is
  regenerated by `update`, which is why the rewrite lives in `Prepare` and not in `config`. A
  missing, unreadable or malformed json is an error naming the file; nothing is written.
- S5. A heap larger than the machine's total memory is refused before the process starts, with the
  requested value and the machine's total in the message, because the JVM would only fail later with
  a cryptic error in the log.
- S6. The TUI shows a `Memory` field (for example `empty uses 8g`) on the create form and on the
  settings form, only for Project Zomboid, and it round-trips through the backend.
- S7. `gamehost show` and `config` without flags print the memory, `8g (default)` when unset.
- S8. `docs/design.md` and `docs/manual.md` document the flag, the default and where the value is
  applied.

Context: the live `zomboid` instance was created in this session and runs with the server's own
`-Xmx8g` (~9.3 GB RSS on a 30 GB machine). Mods stay out of scope. `update` re-runs SteamCMD
`validate`, which restores `ProjectZomboid64.json`, so a one-off edit would not survive an update:
the value has to be re-applied on every launch.

### L2

Decision: the driver owns `-Xmx`, gamehost never touches `-Xms` or any other vmArg. The json is
written before the process starts and only when the bytes change, so `ps` and the file agree and a
restart without changes does not rewrite the file.

### L3 (2026-11-08)

Built and verified on the live `zomboid` instance (Project Zomboid build from SteamCMD, 30 GB machine):

- `gamehost config zomboid --memory 4g` stored `"memory": "4g"` in `instance.json` and left
  `ProjectZomboid64.json` untouched, as designed.
- `gamehost start zomboid --detach` rewrote the launcher to `-Xmx4g`, every other vmArg kept:
  `['-Djava.awt.headless=true', '-Xmx4g', '-Dzomboid.steam=1', '-Dzomboid.znetlog=1',
  '-Djava.library.path=linux64/', '-Djava.security.egd=file:/dev/urandom', '-XX:+UseZGC',
  '-XX:-OmitStackTraceInFastThrow']`.
- The launcher confirms what reached the JVM: `pzexe: vmArg (json) 2: -Xmx4g`, then
  `*** SERVER STARTED ****` and both ports listening.
- Peak RSS dropped from 8.9 GiB (`-Xmx8g`) to 5.0 GiB (`-Xmx4g`); available RAM went from 10 GiB to
  14 GiB.
- `config zomboid --memory 64g` then `start` refused before the process existed:
  `start instance "zomboid": memory 64g is more than this machine's 30g: invalid instance`, exit 1,
  the launcher still `-Xmx4g`, phase `stopped`.
